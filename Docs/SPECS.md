BCTV ACCOUNT AND CHANNELS CREATION.
BCTV: this in meaning is Broadcasters Community Television.
One-User-One-Account, and, One-Account-Multiple-Channels. Meaning, every user can only create and
own just one account, but can create multiple channels under a single account created.
The primary user accounts are created with real/legal names of the account holders. The primary
account shall have the following set up requirements:
*REAL NAME [First and Last Name]: this is required. Automatically made public.
*CAMERA/NICK NAME: this is optional. Automatically made public.
*DATE OF BIRTH: this is required and public, but the year of birth is not made public by system default.
User can keep the entire DOB info private or public.
*PROFILE PHOTO: this is required and made public.
*SHORT BIO/Tell Us About You: this is required and it’s automatically made public.
*HOBBIES: this may be skipped at the point of registration, and can be fulfilled later. Automatically
made public.
*ACTIVE EMAIL: these is required for database purposes.

BROADCASTERS COMMUNITY TELEVISION LIVESTREAMING DOCUMENTATION.
The Broadcasters Community Television project is a traditional TV transmission ideology within the
digital space, creatively driven by modern technology that makes television broadcasting more
accessible and useful for both starters and professionals in the TV broadcast industry.
*On the BCTV platform, it is intended that users shall be able to livestream crystal clear quality
audiovisual content anytime, and without limitations to pre-recorded video files uploaded thereon.
CAPTIONS AND DESCRIPTIONS:
Every BCTV live broadcast must be given a caption at least, before the system activates the livestream. A
livestream can have both a given caption and also description. No live broadcast shall stream with zero
caption, but would livestream without a description.
The system shall always prompt users to write caption for their live broadcast “Marked Required”
before livestream can be activated. Written description “Marked Optional” only would not activate the
livestream, except with caption, but only caption “Marked Required” would activate the livestream.
EDIT FIELD LIMITATIONS:
*Field to write caption for live broadcast shall be 120 character limit.
*Field to write description for live broadcast shall be 1000 character limit.
The BCTV Users dashboard/backend versus frontend designs:
_The frontend button that prompts user to like posted content across the system is titled; APPROVE
_The frontend button that prompts user to dislike posted content across the system is titled;
DISAPPROVE
_Every BCTV user accounts, channels, and posts created across the system shall be editable to add,
remove or replace items, even after publishing successfully.
*Backend: The button that prompts users to write caption for their live broadcast is tagged as: CREATE
LIVE BROADCAST CAPTION – and the button is marked required.
*Frontend: On the frontend, the written caption is automatically displayed on the screen once the
livestream is activated.
*Backend: The button that prompts users to write description for their live broadcast is tagged as:
CREATE LIVE BROADCAST DESCRIPTION – and the button is marked optional.
*Frontend: On the frontend, there is a button tagged: VIEW LIVE BROADCAST DESCRIPTION – So when
clicked, it displays the description and can be closed/minimized afterwards.
BCTV Live Chat And Comment Section:
Backend: While setting up the live broadcast tools and features, users shall have a button tagged:
ACTIVATE LIVE CHATROOM – This is marked optional. If activated, the fans shall be able to comment
during the live broadcast, and if not activated, fans shall not be able to interact live. Meaning, the
comment section is completely blocked for the livestream.
BCTV LIVESTREAM MANAGER FEATURES:
Only owner of the account sees this “frontend” button “Livestream Manager” on the screen during live
broadcast, the audience don’t see it at all. When user/account owner click the LIVESTREAM MANAGER
“frontend” button, a couple of options are found therein.
*LOCK CHATROOM: account owner or admin officers assigned can immediately use this feature during
the livestream to restrict the entire comment section based on public submissions that violates
community rules of engagement.
*UNLOCK CHATROOM: account owner or admin officers assigned can quickly use this feature during the
livestream to allow comments again in the chatroom section.
*Also, the account owner or Admin managers assigned to the given channel in real time can block
individual commentator with submission that violates rules of engagement.
*Registered users are able to report other individual/registered users based on conducts that violates
the rules of engagement.
*There shall be a player control setting feature within the system, wherein users can control how
normal, faster, or slower a given uploaded file can play. Only live broadcast plays normal by default.
*Account owner or admin officers shall be able to pin posts made in the comment section.
*When the comment section is locked by the account owner, the fans/audience shall see a “padlock”
image on the comment section feed with a text that says: CHATROOM HAS BEEN RESTRICTED.
NB: Viewing live broadcast descriptions or captions of the images uploaded or reading comments in the
chatroom or replying comments either by the account owner or fans shall not interrupt the livestream
or the playing audio content in progress.
APPROVE AND DISAPPROVE FEATURES:
Here, we use “APPROVE / DISAPPROVE” features instead of the traditional “Like and Dislike” features.
Meaning, users would only get to APPROVE or DISAPPROVE contents on this platform.

BCTV SIMULCAST i.e Simultaneous Livestreaming:
This is an advance BCTV feature and it is paid for. Meaning, it is only subscription based. Account owners
would have to subscribe to the advance feature in order to be able to activate simulcast feature both on
your personal account and channels, and also on the accounts and channels of other creators.
Users shall only be able to livestream just a content on one channel at a time using the same device,
unless the primary account owner signs-in on other channels created using different devices.
User shall be able to relay or carry the livestream of channel 1 on channel 2 or more. Meaning, if
channel 1 is broadcasting live football match, same livestream can be made to transmitting live at the
same time on channel 2 or more. This is different from multiple channels broadcasting different content
at the same time, which will be impossible, but if it is the same content, then it can be relayed on
multiple channels simultaneously.
Still on simultaneous livestreaming. Aside the channel brand identity of the secondary channel or
channels transmitting a given simulcast, there shall be a system custom logo or badge that says, (LIVE
SUGAR ORANGE SIMULCAST), that is, if name of the primary channel that initiated the live broadcast is
“Sugar Orange”. The logo or badge shall be visible on the screen of other secondary channels relaying
the simulcast, so it’s known to the audience that the broadcast is a simulcast from the mentioned
primary channel. Meaning, two brand identities shall be on the screen, one for the host channel, and
one for the primary channel broadcasting content being relayed.
The simulcast possibility can happen within a single account of a given creator with multiple channels
created, and also shall be possible via multiple accounts. Meaning, an account called SUGAR ORANGE
with 500 subscribers shall be able to simulcast within own account with multiple channels. Also, the
SUGAR ORANGE creator can have a simulcast deal and agreement with a different account owned by a
different creator with 5000 subscribers. Simply put, account owner with smaller subscribers shall be able
to pay a different account owner with bigger subscription advantage for a better visibility through
simulcast on their own channels.
For instance, 1000 subscribers per hour or for 2 hours or more. So the interested creator is paying per
number of subscribers the other creator has, and for the number of hours the simulcast is desired on a
bigger platform. The system shall handle the timing set for the simulcast, that is if one hour is paid for,
the connection is established when it’s due and disconnect when the 60 minutes are gone.
On all accounts subscribed to this feature, there shall be a button tagged (SIMULCAST PROJECTS) and it
is a folder where all simulcast projects are found both on accounts of who paid for the simulcast deals
and also who received payments for the simulcast deals. The simulcast project folder is subdivided into
two parts, wherein one is named (PERSONAL) and the other is named (PROMOTION). The Personal
projects are content primarily initiated by the account owner, while the Promotion folder contains
simulcast content paid for by other creators. The simulcast projects are permanently thereon by default,
having all features stated above about content across the platform.
The simulcast deals and payments shall happen within the platform between creators, and the system
will manage the deals, collect the payments, take a percentage, and pay the balance to the due creator.
That’s if an agreement is reached between the creators. However, no such deal is required if the
simulcast is happening within same account thereon multiple channels created.
RECORDING BCTV LIVE BROADCAST:
While setting up the livestream tools and features, the user shall find a button tagged: RECORD LIVE
BROADCAST – This is marked optional, but if activated, the live broadcast would begin to record when
the livestream activates. Meaning, the system shall be able to record live broadcast, and the recorded
file saves on the channel automatically.
OFFLINE RECORDING:
User shall be able to make offline recording on the BCTV system. Meaning, without streaming live, user
can click on “OFFLINE RECORDING” and the action button activates the recording mode with indicators
of the recording showing on the screen. When user is done recording, the recorded file saves right inside
the Offline Recording folder, and user can rename the file as preferred, and also user can share the URL
generated, or simply download the file onto own personal device.
LIVE STREAM MANAGER FEATURE:
As already stated above, only owner of the account sees this “frontend” button “Live Stream Manager”
on the screen during live broadcast, the fans don’t see it at all. When user/account owner click the
“frontend” LIVE STREAM MANAGER button, a couple of more options in addition to just two mentioned
above are found thereon the window displaying.
*LOCK CHATROOM
*UNLOCK CHATROOM
*PAUSE RECORDING – this button/feature puts the live broadcast recording in progress on hold.
*RESUME RECORDING – this button/feature resumes the live broadcast recording from the paused
point.
*STOP RECORDING – this button/feature terminates the live broadcast recording completely and save
file automatically onto user’s device.
*START LIVE STREAM – this button/feature automatically activates all tools/features/settings already
prepared for the live broadcast.
*PAUSE LIVE STREAM – this button/feature puts the live broadcast on hold.
*RESUME LIVE STREAM – this button/feature resumes the live broadcast from the paused point.
*STOP LIVE STREAM – this terminate/end the live broadcast completely.
Sound Card Selection For Livestreaming:
The system shall be able to choose/switch automatically between the inbuilt microphone/camera or
external soundcard devices for live broadcasting. Meaning, if no soundcard like the “Audiovisual Mixer”
is connected to the device in use, the system would automatically activate the inbuilt
microphone/camera of the [PC or Mobile] device in use for the live broadcast.
BCTV AUTOMATION FEATURE:
This is user’s backend/dashboard feature. Traditionally it is called or known as “Play On Demand”, more
like a folder where users can drop one or multiple audio files such as songs etc. The user can then
activate the system to keep playing the contents uploaded onto the folder. Meaning the content would
play continuously offline to keep the channel online even when the user is offline until the automation
system is deactivated. Also, activating a livestream takes down the automation system automatically,
and it resumes automatically to playing content once the livestream is deactivated.
Please create this feature and tag the action button as: (BCTV AUTO LIVESTREAM) ___ and it shall
function to perform the above descriptions. In addition, the “AUTO LIVESTREAM” system shall have
other extra features like:
*ACTIVATE PLAYLIST _-_ this plays everything nonstop.
*DEACTIVATE PLAYLIST _-_ this stops the system completely.
*SHUFFLE PLAYLIST: this plays selected files randomly.
*DELETE PLAYLIST: this wipes out the entire playlist uploaded.
*UPLOAD PLAYLIST: this drags selected folder of files from the user’s device onto the system.


BROADCASTERS COMMUNITY TELEVISION LIVE VIDEO CALLS DOCUMENTATION:
This BCTV live video call feature shall be a part of the “Livestream Manager” menu, wherein registered
users are able to relate in real time with the livestreaming broadcaster.
*Frontend feature and only account owner sees: (ACTIVATE LIVE AUDIENCE PARTICIPATION
CHATROOM), and this button once activated allows the listening audience to click a button to join and
interact live with host of the live broadcast.
*Frontend feature and only registered user sees: (JOIN LIVESTREAM STUDIO CHATROOM), and this
allows just one listening audience at a time to speak. However, there can be up to five
callers/participants on the waiting room and in queue, but only one speaks at a time.
*Frontend feature and only account owner sees: (ACCEPT NEW LIVE STUDIO INTERRACTION), and this
button when activated allows the host to take incoming calls.
*Frontend feature and only account owner sees: (END LIVE STUDIO INTERRACTION), and this feature
allows the host to terminate the call in progress.
*Frontend feature and only account owner sees: (DEACTIVATE LIVE AUDIENCE PARTICIPATION
CHATROOM), and this feature completely closes the opportunity for live studio interactions.
